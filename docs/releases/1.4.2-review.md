# Scope → Snurpo: identity, native icons and real workflow gallery

The repository has moved to `dalkedev/snurpo`. This change makes the application,
current documentation and artwork match the new name, adds the curious Snurpo
mascot to desktop icons and the macOS menu bar, and replaces the current gallery
with real native captures of inspecting, mocking and replaying HTTP traffic.

The first-run screen makes local test traffic easy to discover. Lavender and
mint interaction colors match the mascot; light appearance receives readable
semantic text colors. Existing-rule empty-editor copy no longer tells users
to create their first rule.

## Compatibility and history

Existing sessions, CA trust and automation integrations keep their established
identifiers: app/data identity, database and export formats, executable names,
environment variables, Android runtime identities and MCP settings. The new
`snurpo-har-compare` command is an alias; the previous command remains available.
See `docs/MIGRATING_TO_SNURPO.md` for the explicit compatibility inventory.

Old artwork and provenance are retained under `assets/brand/legacy`, and previous
releases and historical verification evidence remain truthful. Current artwork
has its own provenance, source prompts and hashes. Gallery images are actual
native screenshots without the cursor, using only local fixture traffic.

## Validation

- Production frontend build and UI tests; Rust workspace, HAR CLI, device Python,
  Frida, release and license tests passed locally.
- Native macOS package, ad-hoc signature and bundled resource verification passed.
- Real local capture, MCP access gates, persistence and restart smoke passed.
- Native walkthrough: six fixture requests, a saved local 503 mock, an edited
  POST replay returning 200, session analysis, Stop capture and native Quit.
- Exact test counts and post-polish checks are recorded in
  `docs/verification/2026-11-12-snurpo-rebrand.md`.
- Required Windows, Ubuntu and macOS CI must pass on this proposal before merge.

Menu-bar icon rendering and its Show/Quit actions still need a direct native
review. No new Android or Windows/Linux interactive verification is claimed.
The local build is ad-hoc signed, not notarized; the local toolchain emitted a
non-fatal missing-libLLVM warning during symbol stripping.
