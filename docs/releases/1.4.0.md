# Scope 1.4.0 — an owned Android engine and clearer evidence

The workspace now has **Light**, **Dark** and **System** appearance modes. Choose
one under Appearance in the sidebar. Your preference stays on this device;
System follows live desktop changes. Inspectors, request/body editors, rules,
diagnostics and dialogs share the dark palette and retain semantic status colors.

The MCP SDK is updated to 3.9.0, with refreshed bundled notices. Vitest 5.1.0
supports the regression suite. An additional archive diagnostic control now
binds recorded URLs to the fixture target actually sent, so consistent corruption
of both captured URL fields cannot pass the diagnostic's evidence check.

Android Frida mode now uses Scope's experimental `scope-java-v1` Java engine.
It configures supported Java proxy connections, validates intercepted chains
against the supplied Scope CA, and bypasses supported ordinary OkHttp3 pins only
for valid Scope chains. Original hostname, expiry and unrelated-chain checks
remain active. The retained Frida Java bridge and its notices remain included.

Stop now ends the exact application process spawned by the active worker before
unloading hooks. Successful cleanup restores Start, so capture can reconnect
without restarting Scope. Reopening an active device panel preserves its actual
Frida mode. Failed or uncertain cleanup retains recovery state for reconciliation.
Worker output framing and retained diagnostics also have explicit size limits.

The [recorded Android acceptance](https://github.com/dalkedev/scope/blob/v1.4.0/docs/ANDROID_ACCEPTANCE.md)
includes 75/75 synthetic HTTP/TLS outcomes and two worker Stop/restoration gates
on AOSP Android 16/API 36 ARM64, Frida 17.9.1 and OkHttp 3.14.9. Separate native
macOS arm64 checks captured real HTTP 200 responses and JSON through Scope over
two Start/Stop cycles, with owned process/mapping cleanup and reconnect.

## Android upgrade notes

The new backend has reduced coverage compared with the removed imported hooks.
Root hiding and system-CA injection are removed. Native TLS, Cronet, QUIC, Flutter,
child processes and custom/obfuscated pinners are unsupported. Recognized lazy
OkHttp/Kotlin `check$okhttp` configurations fail before readiness; a genuine
OkHttp 4.9.3/Kotlin fixture verified that rejection and cleanup, not unpinning support.
Missing requested capabilities fail startup. Select explicit supported profiles
when the default proxy/certificate/unpinning combination is unavailable.

System proxy mode remains device-wide; HTTPS requires manually configured app
trust. Optional native Frida worker/server binaries are excluded from public
packages and can be installed with the included setup helper. Back up important
captures and finish pending device cleanup before upgrading.

## Archive diagnostics

A new opt-in synthetic harness records bounded save-phase, timer and loopback
responsiveness evidence with hard child-process deadlines and cleanup controls.
The [Linux/Windows results](https://github.com/dalkedev/scope/blob/v1.4.0/docs/ARCHIVE_RESPONSIVENESS.md)
retain their exact historical Scope 1.2.2 source; a separate post-merge smoke checks
compatibility. Production archive writes, SQLite durability and capture limits
are unchanged. No production throughput improvement is claimed.

## Platform and licensing notes

Packages target macOS arm64, Windows x64 and Linux x64. Verify `SHA256SUMS.txt`
and each build manifest's source commit. macOS is ad-hoc signed without Apple
notarization. Interactive Windows/Linux, Intel macOS, physical Android devices,
other Android API/ABI combinations and crash/restart recovery with an active
Android worker remain unverified. This release does not establish general
Android compatibility. Bodies above 16 MiB, WebSocket frames and HTTP/3 retain
their existing limits.

**AGPL-3.0-or-later.** Third-party provenance and the verified GLib 0.18.5 iterator
backport remain included. The owned hooks do not imply a legally certified
clean-room implementation.
