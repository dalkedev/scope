# Snurpo 1.4.2: a nosy little HTTP debugger

Scope is now **Snurpo**. This is the first release with the new mascot, desktop
icons and Snurpo-branded downloads. Your saved sessions, trusted CA and MCP
configuration keep their existing compatibility identifiers.

## What's new

- A curious mascot in the application, desktop icon and macOS menu bar. The
  menu offers **Show Snurpo** and **Quit Snurpo**.
- A clearer first run: **Generate test traffic** sends real localhost requests
  through the capture engine so you can immediately explore the inspector.
- Lavender selection/focus accents, mint brand details and corrected contrast
  in Light appearance. The rules editor recognises an existing saved rule.
- A fresh native screenshot gallery showing response inspection, a saved 503
  mock, an edited POST replay and session analysis. The redundant `local` badge
  beside the logo is gone.
- Node.js **26.13.1 LTS** for source builds and the offline HAR CLI. The installed
  native app does **not** require Node. Branded HTML fixtures and Linux bundling
  prerequisites are corrected; report safety checks remain enabled.

## Downloads and upgrading

- **macOS Apple Silicon:** `Snurpo-v1.4.2-macOS-arm64.zip` contains `Snurpo.app`.
- **Windows x64:** `Snurpo-v1.4.2-Windows-x64-setup.exe`.
- **Linux x64:** AppImage and Debian package.
- **Source:** `Snurpo-v1.4.2-source.zip`; verify downloads with `SHA256SUMS.txt`.

Quit Scope before opening Snurpo. On macOS, move `Snurpo.app` to Applications
and keep one installed/running copy: both names access the same local archive.
Do not rename the database, CA or bridge files. The underlying executable and
integration identifiers intentionally retain compatibility names. See the
[migration guide](https://github.com/dalkedev/snurpo/blob/v1.4.2/docs/MIGRATING_TO_SNURPO.md).

## Platform notes

The macOS app is ad-hoc signed and **not Apple-notarized**. Windows/Linux builds
have automated package and headless engine/MCP coverage; their interactive
installers, upgrades and device behaviour remain experimental. Intel macOS is
unverified. The Linux package includes an AppIndicator dependency required by
the current Tauri bundler; the tray interface is macOS-only.

Optional native Frida binaries are excluded. Install that runtime separately
using the shipped setup helper for supported Android instrumentation. Previous
Android acceptance applies only to its documented target; this branding release
does not broaden device support. Existing dependency findings and platform
limits remain in the
[verification record](https://github.com/dalkedev/snurpo/blob/v1.4.2/docs/VERIFICATION.md)
and [dependency notes](https://github.com/dalkedev/snurpo/blob/v1.4.2/docs/DEPENDENCIES.md).

Historical Scope releases and their checksums remain unchanged.
