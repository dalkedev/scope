# Add captured-request cURL export in Snurpo 1.5.0

The inspector can replay or copy a URL, but cannot carry a complete captured
request into a terminal. **Copy as cURL** adds an explicit POSIX-shell preview
and clipboard action, preserving text/binary bodies and repeated headers while
normalizing transport framing. Previewing and copying send no traffic.

This proposal integrates PR #38 without rewriting its history, resolves its
conflicts against the Snurpo rebrand and preserves Node 26.13.1 and current
appearance. The feature and release preparation supersede that original draft.
Application/npm/Rust/Tauri versions advance to **1.5.0**; HAR remains 0.1.0.
Bundled notices are regenerated from the lockfiles without modifying upstream
license text. Existing data and integration identifiers remain compatible.

## Validation

- Node 26.13.1: 87 tests in 12 files passed, including generator, clipboard,
  same-request preview changes and the inspector entry point. Production
  TypeScript/Vite build passed.
- Real macOS sh/zsh + cURL loopback tests cover text POST, binary GET with all
  256 byte values, empty POST and HEAD. Exact target, method, body and
  repeated/empty headers are asserted. Captured shell-looking strings stay literal.
- Independent security/correctness review found no blocking issue after separate
  sh/zsh binary-byte and quoting probes. All execution used synthetic localhost
  data. Dependency installation reported zero npm vulnerabilities.
- Native GUI clipboard acceptance and exact-commit Windows/Ubuntu/macOS CI must
  be checked separately before publication. Tagged draft assets require their
  own checksums, package-resource and engine/MCP verification.

The command is for POSIX shells, not PowerShell or cmd.exe. Captured credentials
are intentionally disclosed before copying; this is not a sanitized export.
Malformed or oversized inputs and HEAD bodies fail visibly. TLS verification
stays enabled; curlrc, retries and automatic redirect following are not added.
Windows/Linux interactive and Android coverage remain at their documented limits.
