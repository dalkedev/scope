# Scope 1.1.0: Find the request. Check the change.

Scope 1.1.0 adds structured desktop traffic filters, an offline HAR comparison
tool for CI and a smaller allocation footprint during native session imports.
Existing capture, replay, archive formats and free features remain available.

## Structured traffic search

Find failed POST requests with `filter: method=POST status>=500`, narrow to an
exact host, search plain request/response text, or combine lifecycle and edited
conditions. Filters run before pagination. Ordinary text keeps its previous
literal behavior, and inline syntax help includes examples.

[Search syntax and boundaries](https://github.com/dalkedev/scope/blob/v1.1.0/docs/SEARCH.md)

## Offline API change evidence

The source archive includes the dependency-free `tools/har-compare` Node CLI.
Compare saved HAR files, select exact operations, ignore volatile JSON fields
per endpoint and author explicit allowed-status/required-field/type contracts.
Export deterministic JSON, escaped offline HTML and JUnit for a CI job.

Exit `0` means no configured regression, `1` identifies regression candidates,
and `2` means the analysis was invalid or incomplete. An unchanged HTTP 500 can
pass observation mode; author a status requirement to reject it. Repeated calls
pair by encounter order, so reordered/request-body-dependent calls may remain
ambiguous. Reports omit captured scalar values, headers, cookies and query data;
readable host/path/field labels still require review before sharing. `--labels ids`
reduces labels rather than guaranteeing anonymity.

[CLI and runnable examples](https://github.com/dalkedev/scope/blob/v1.1.0/tools/har-compare/README.md)

## Leaner native imports

Native import now consumes its already-owned exchange JSON tree instead of
cloning the complete tree. Validation and the atomic SQLite transaction remain.
Recorded bounded Linux debug-profile tests with 64 MiB of decoded bodies show
about 31–33% lower absolute process peak RSS. These measurements are not a
release-build speed claim or a general memory bound. Streaming remains future work.

[Reproduction, raw measurements and limitations](https://github.com/dalkedev/scope/blob/v1.1.0/docs/NATIVE_IMPORT_MEMORY.md)

## Packages and verification

The release targets macOS arm64, Windows x64 and Linux x64, with a source ZIP,
platform build manifests and SHA-256 checksums. The HAR CLI is available from
the source ZIP and requires Node 22.22.3 or newer. Optional native Frida binaries
remain separate upstream installations and are not bundled in public packages.

Verify the downloaded asset against `SHA256SUMS.txt` and inspect its platform
build manifest for the exact source commit. Cross-platform CI covers locked
workspace/frontend tests, packaging and headless desktop/stdio MCP smoke; the
HAR workflow independently checks hostile report handling and Chromium/CSP.

Interactive desktop/device validation for this version remains unperformed
unless explicitly recorded in the release verification results. Earlier macOS
and Android observations apply to their documented versions. The macOS package
is ad-hoc signed, without Apple notarization. Windows/Linux interactive behavior
remains experimental. Existing dependency limitations are listed in
[the dependency record](https://github.com/dalkedev/scope/blob/v1.1.0/docs/DEPENDENCIES.md).

Back up important captures before upgrading. Bodies remain buffered up to 16 MiB
each; WebSocket frames, trailers, HTTP/3 and large-session streaming are not added.
