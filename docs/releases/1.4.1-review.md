# Scope 1.4.1: patched SQLite and final release review

A fresh RustSec audit of the 1.4.0 candidate found RUSTSEC-2026-0459 in
bundled libsqlite3-sys 0.36.0. The 1.4.0 tag and draft remain unchanged and
unpublished. This proposal updates rusqlite and its bundled SQLite to the patched
line, verifies the actually linked runtime, refreshes notices and adds a fresh
registry-advisory audit to Linux checks and tagged release builds. No advisory is
ignored; the existing GLib path-backport limitation and unmaintained warnings
remain explicit.

The inherited scope is the already reviewed 1.4.0 tree: persistent Light/Dark/System
appearance, the experimental Scope-owned Android Java engine with owned-process
Stop/reconnect, archive measurements and the independently reviewed target-bound
evidence detector (#34). MCP SDK 3.9.0 and Vitest 5.1.0 remain. No production
archive throughput improvement is claimed.

Before approval, require final locked tests, fresh audit, GLib integrity, notices,
three-platform checks and CodeQL on the frozen head. Inspect exact-tag draft assets,
checksums, manifests, source bytes and package contents before publication. Preserve
all version tags, branch protections, owner captures and actual commit authorship.

Android evidence remains limited to API36 ARM64, Frida17.9.1 and OkHttp3.14.9:
75 controlled worker outcomes and two native capture/Stop cycles. Lazy Kotlin,
native TLS and other unsupported stacks retain their explicit boundaries. Active
worker crash/restart and interactive Windows/Linux/other Android targets remain
unverified. Fresh SQLite tests do not establish those separate device workflows.
