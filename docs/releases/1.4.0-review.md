# Scope 1.4.0: Android engine and archive diagnostics review

This proposal integrates the reviewed Android engine (#32) and bounded archive
investigation (#30). Frida Stop now terminates the exact worker-spawned app process
and successful cleanup restores Start. The new Scope-owned Java hooks replace
the imported runtime with narrower, explicit capabilities. Archive diagnostics
add reproducible evidence without changing production persistence scheduling.

The candidate also adds persistent Light/Dark/System appearance. The startup
preload and React control share preference semantics; System follows live changes.
Semantic dark color roles cover all existing workspaces and keep the original
light palette as fallbacks. Appearance never changes capture or device state.

PR #34 additionally binds diagnostic evidence to the actual fixture target,
including consistent corruption of both recorded URL fields. This remains
test-only. Reviewed dependency updates #35/#36 bring Vitest 5.1.0 and MCP SDK
3.9.0, with regenerated notices. The preload test uses the HTML parser to respect
HTML tag semantics and remove the CodeQL regular-expression finding.

## Behavior and compatibility

- `scope-java-v1` uses the unchanged third-party Frida Java bridge. A separate
  Scope-only trust manager validates the chain before supported certificate/pin
  exceptions can be overridden. Hostname, expiry and unrelated failures retain
  original checks. No trust-all manager or system-CA injection is installed.
- Requested profiles must report the exact installed capabilities before ready.
  Ordinary Java OkHttp3 overloads target the tested 3.14.9 implementation. Lazy
  Kotlin `check$okhttp` configurations reject startup transactionally, including
  classes that also expose ordinary public overloads. Root hiding, native TLS,
  Cronet, QUIC, Flutter, child processes and custom/obfuscated pinners are unsupported.
- Stop requires matching owned-process cleanup evidence and successful worker
  exit. Uncertain spawn/cleanup retains recovery; saved target PIDs are never
  killed during recovery. Existing mapping ownership guards remain. Successful
  cleanup clears stale device identity; reopened active panels preserve Frida mode.
- Worker pipe frames and retained logs are bounded before JSON parsing/storage.
  Invalid stdout is a sticky protocol failure; later receipts cannot erase it.
  These are diagnostic allocation limits, not a total-memory or throughput claim.
- System proxy mode remains device-wide and HTTPS needs manually configured app
  trust. Optional native Frida binaries remain excluded from public packages.
  Coverage is reduced from the removed backend; no legal clean-room claim is made.
